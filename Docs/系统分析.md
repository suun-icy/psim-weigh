## 1、项目整体架构

### 1.1 项目概况

| 属性 | 说明 |
|------|------|
| 项目名称 | pism-weigh（地磅称重软件） |
| 技术栈 | .NET Framework 4.7.2 + Windows Forms（WinForms） |
| 输出类型 | WinExe（桌面应用程序） |
| 开发语言 | C# 5.0 |
| 界面框架 | System.Windows.Forms |
| 本地数据库 | SQLite 3（通过 System.Data.SQLite） |
| JSON 处理 | Newtonsoft.Json 13.0.4 |
| 解决方案 | 单个项目，单条主分支 |

### 1.2 分层架构

项目采用**松耦合的分层架构**，按目录组织为五层：

```

│  Form1.cs       — 主窗口（称重操作、串口管理）          │
│  UserLogin.cs   — 用户登录窗口                        │
│  print.cs       — 打印设置窗口（占位，未完成）           │

├──────────────────────────────────────────────────────┤
│                  服务层 (Services)                     │
│  ScaleService.cs — 地磅仪表串口通信服务                 │
│  PrintService.cs — 打印服务（多模板）                   │
├──────────────────────────────────────────────────────┤
│                  数据模型层 (Models)                    │
│  WeighRecord.cs   — 称重记录实体 + 4个枚举             │

├──────────────────────────────────────────────────────┤
│                  数据访问层 (Database)                  │

## 5、称重流程

### 5.1 两次称重法（标准流程）

这是地磅称重的核心业务流程：

```
第一步：称取重车（毛重 GrossWeight）
    │
    ├── 前提：串口已打开，重量数据实时显示在 textBox6
    ├── 前提：填写车牌号（省份简称 + 号码）
    │
    ├── 点击"称取重车"按钮 (button2_Click)
    │       ├── 校验：车牌号不为空
    │       ├── 校验：称重不为空（textBox6 有数据）
    │       └── 将 textBox6（实时重量）→ 填充到 textBox1（重车）
    │
第二步：称取空车（皮重 TareWeight）
    │
    ├── 点击"称取空车"按钮 (button4_Click)
    │       ├── 校验：车牌号不为空
    │       ├── 校验：称重不为空
    │       └── 将 textBox6（实时重量）→ 填充到 textBox2（空车）
    │
第三步：计算净重
    │
    └── 点击"计算"按钮 (button5_Click)
            ├── 校验：车牌号不为空
            ├── 校验：textBox1（重车）和 textBox2（空车）不为空
            ├── 自动判断：毛重(重车) < 皮重(空车) 时静默处理（不报错）
            └── 计算：净重 = 毛重 - 皮重 → textBox3
```

### 5.2 完整称重-打印-上传流程

```
车辆上磅
    │
    └── 串口 DataReceived 事件触发
            │
            ├── 解析 ASCII 协议数据
            ├── 提取重量数值（等号后的数字，去前导零）
            └── 显示在 textBox6（实时重量大字显示）
    │
称取重车 → textBox1 = 当前重量
    │
车辆下磅卸货
    │
车辆再次上磅
    │
    └── 串口 DataReceived → textBox6 更新
    │
称取空车 → textBox2 = 当前重量
    │
计算 → textBox3 = textBox1 - textBox2
    │
打印按钮 (button7_Click)
    │
    ├── 检查登录状态
    ├── 构造数据对象
    ├── 上传至服务器
    └── 清空界面字段
```

### 5.3 ScaleService.cs 中的高级称重功能（尚未集成）

`ScaleService` 提供了比 Form1 内置代码更完善的称重功能：

- **多协议解析**：ASCII 格式（等号/GS前缀）、STX/ETX 帧格式、直接数字格式
- **事件驱动架构**：WeightReceived / ConnectionStateChanged / ErrorOccurred 事件
- **稳定重量检测**：`GetStableWeightAsync()` 持续采样直到连续5次变化小于阈值
- **指令发送**：支持向仪表发送控制命令
- **串口参数配置**：Set DtrEnable / RtsEnable

## 6、串口通信流程

### 6.1 串口参数配置

```
界面配置项（在 Form1.panel1 中）：
    ├── 串口号   (comboBox1) : 动态扫描可用串口
    ├── 波特率   (comboBox2) : 600/1200/2400/4800/9600（默认600）
    ├── 数据位   (comboBox3) : 8（唯一下拉选项）
    ├── 校验位   (comboBox4) : None/Odd/Even/Mark/Space（默认None）
    └── 停止位   (comboBox5) : 1/0（默认1；注：0 不是标准停止位）
```

### 6.2 串口生命周期

```
打开串口 (button1_Click)
    │
    ├── 检查是否已打开
    │       ├── 已打开 → Close() → 更新UI状态为"已关闭"
    │       └── 已关闭 → 配置参数 → Open() → 更新UI状态为"已打开"
    │
    └── 异常处理
            ├── 重新创建 SerialPort 对象
            ├── 刷新可用串口列表
            ├── 蜂鸣告警
            └── MessageBox 显示异常信息
```

**⚠️ 注意**：停止位下拉框中包含 "0" 选项，但 .NET `StopBits` 枚举只有 `None(0)/One(1)/Two(2)/OnePointFive(3)`，`StopBits.None` 不是合法的串口参数，如果用户选择了 "0" 会导致异常。

### 6.3 数据接收与解析（核心）

```
serialPort1_DataReceived 事件（Form1 内置实现）
    │
    ├── 获取缓冲区大小 (ReadBufferSize)
    ├── 创建接收缓冲区
    ├── 累加接收字节计数 (receive_count)
    │
    ├── Invoke 回到 UI 线程
    │       │
    │       ├── 模式判断：radioButton2.Checked
    │       │       │
    │       │       ├── HEX 模式 → 逐字节转为 2位16进制显示（"X2 "）
    │       │       │
    │       │       └── ASCII 模式 → 协议解析：
    │       │               │
    │       │               ├── 读取第一个字节
    │       │               ├── 判断是否为 0x02 (STX 帧起始)
    │       │               │       ├── 是 → 循环读取直到 0x03 (ETX 帧结束)
    │       │               │       │       每字节存入 received_buf
    │       │               │       └── 否 → 不处理
    │       │               │
    │       │               ├── Array.Reverse(received_buf)
    │       │               ├── ASCII 解码
    │       │               ├── 提取等号后面的数字部分
    │       │               └── 去前导零 → textBox6.Text（显示重量）
    │       │
    │       └── 追加原始数据到 textBox_receive（日志窗口）
    │
    └── 更新 Rx 字节计数状态行
```

### 6.4 地磅仪表通信协议

根据代码分析，系统支持以下协议格式：

| 协议类型 | 格式示例 | 解析方式 |
|----------|----------|----------|
| **等号格式** | `=12345` | 取 `=` 之后的数字，去前导零 → `12345` |
| **STX/ETX帧** | `0x02` + 数据 + `0x03` | 剥离 STX/ETX 后 ASCII 解码，再按等号格式取值 |
| **GS 前缀** | `GS,+   12.345kg` | 取 `GS,` 之后的数字部分（ScaleService 支持） |
| **直接数字** | `12.345` | 直接提取数字（ScaleService 支持） |

**当前 Form1 实际使用的协议**：等号格式，含 STX/ETX 帧包装（`0x02 =12.345 0x03`）

### 6.5 手动指令发送

```
发送指令 (button8_Click)
    │
    ├── 检查串口是否打开
    └── serialPort1.Write(textBox4.Text)
```

### 6.6 ScaleService.cs vs Form1 内置代码对比

| 特性 | Form1 内置 | ScaleService.cs |
|------|-----------|-----------------|
| 协议支持 | 等号格式 + STX/ETX | 等号格式 + STX/ETX + GS格式 + 直接数字 |
| 事件驱动 | 无（直接在事件中处理） | 3个事件回调 |
| 稳定检测 | 无 | 有（`GetStableWeightAsync`） |
| 错误处理 | MessageBox + 蜂鸣 | 事件回调 |
| 集成状态 | **实际使用中** | 待集成 |

### 7.2 PrintService 打印流程

```
PrintService.Print(WeighRecord record, PrintTemplate template)
    │

    ├── 设置打印份数
    │

                    │
                    ├── 绘制标题（"称重单"，宋体20号加粗，居中）

## 8、哪些地方可以扩展

### 8.1 架构层面

| 扩展点 | 当前状态 | 建议方向 |
|--------|----------|----------|
| **MVVM/MVP 重构** | 事件处理全部写在 Form1.cs，代码耦合严重 | 引入数据绑定，分离视图和业务逻辑 |
| **DI 容器** | 无依赖注入，直接 new 对象或用静态方法 | 引入 Microsoft.Extensions.DependencyInjection |
| **ORM 框架** | 手动 ADO.NET + DataTable 映射 | 引入 Dapper 或 Entity Framework 6 |
| **配置管理** | 配置硬编码（如服务器地址在代码中写死） | 引入 appsettings.json + 配置界面 |
| **日志框架** | 无日志系统 | 引入 NLog 或 log4net |
| **单元测试** | 完全无测试 | 分离接口后添加 xUnit/NUnit 测试 |

### 8.2 功能层面

| 扩展点 | 当前状态 | 建议方向 |
|--------|----------|----------|
| **ScaleService 集成** | 已封装但未使用，Form1 用内置代码 | 将 Form1 迁移到使用 ScaleService |
| **PrintService 调用** | 已封装但未使用 | button7 应真正调用 PrintService 打印 |
| **打印设置窗口** | print.cs 是空窗体 | 实现打印模板选择、打印机选择、预览功能 |
| **称重记录管理界面** | 数据库有完整 CRUD API，但无 UI | 添加 DataGridView 列表、搜索、筛选、编辑 |
| **审核工作流** | 数据库有 Category/PendingReview 支持，无 UI | 添加审核界面和操作按钮 |
| **数据导出** | 无导出功能 | Excel/PDF 导出、CSV 导出 |
| **报表统计** | 无统计功能 | 日报/月报/年报，图表可视化 |
| **摄像头集成** | 无 | 称重时自动拍照存档 |
| **RFID 集成** | 无 | RFID 读卡器自动识别车辆 |
| **LED 大屏** | 无 | 实时重量显示到大屏 |

### 8.3 串口通信层面

| 扩展点 | 当前状态 | 建议方向 |
|--------|----------|----------|
| **多协议扩展** | ScaleService 已预留 4 种解析方式 | 增加更多仪表厂商协议适配器 |
| **虚拟串口** | 无 | 支持虚拟串口用于开发调试 |
| **串口配置持久化** | 每次启动重新设置 | 保存/加载串口配置 |

| **多串口支持** | 只支持一个串口 | 支持同时连接多个仪表 |

### 8.5 已知 Bug 需要修复

1. **button7_Click 数据填充错误**：PmsWeightinfo 所有字段都用了 `textBox1.Text`（重车重量），应正确填入各个业务字段（车牌、毛重、皮重、净重等）
2. **停止位选项 "0"**：comboBox5 包含 "0" 选项，`StopBits.None` 不是有效串口参数，会导致打开串口异常
3. **登录失败无提示**：HttppPost 返回空字符串时，UserLogin 直接跳过，用户不知道登录失败
4. **计算净重时未做空车重判断**：当 `毛重 < 空车重` 时只留空 if 块不做任何处理
5. **接收缓冲区未实际读取**：`serialPort1.Read(received_buf, 0, num)` 被注释掉了，HEX 模式下显示的数据实际为空
6. **serverCertificateValidationCallback 全局覆盖**：HTTPS.cs 中 `ServerCertificateValidationCallback = (…) => true` 接受所有 SSL 证书，存在安全风险

### 8.6 安全层面

| 扩展点 | 当前状态 | 建议方向 |
|--------|----------|----------|
| **用户认证** | token 静态存储，无过期检查 | 增加 token 刷新机制 |
| **密码存储** | 明文传输 | 密码加密 + HTTPS |
| **操作审计** | 有 ModifyHistory 字段 | 增加操作日志表记录所有操作 |
| **权限控制** | user.cs 有角色信息但未使用 | 根据角色控制按钮/功能可用性 |
| **SSL 证书验证** | 全部跳过 | 正确验证服务器证书 |
