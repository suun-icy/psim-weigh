## 1、项目介绍

### 1.1 产品概述

psim-weigh 是一款基于 .NET Framework 的 **地磅称重管理桌面软件**，面向工厂、仓库、物流园等需要车辆称重的场景。系统通过串口连接地磅仪表，实时采集重量数据，支持两次称重法（毛重→皮重→净重），并将称重记录保存至本地 SQLite 数据库，同时支持通过 HTTP API 将数据上传至远程 PMS 服务器。

### 1.2 核心功能

| 功能模块 | 说明 | 实现状态 |
|----------|------|----------|
| 串口通信 | 通过 RS-232/RS-485 连接地磅仪表，实时读取重量 | ✅ 已实现 |
| 两次称重 | 毛重（重车）、皮重（空车）、自动计算净重 | ✅ 已实现 |
| 数据存储 | 本地 SQLite 数据库存储称重记录 | ✅ 已实现 |
| 数据上传 | HTTP POST 将称重数据上传至远程服务器 | ✅ 已实现 |
| 用户认证 | 通过远程 API 登录验证 | ✅ 已实现 |
| 打印输出 | 多模板打印称重凭证 | ⚠️ 服务已封装，UI 未集成 |
| 数据审核 | 称重记录修改→审核工作流 | ⚠️ 数据库已支持，UI 未实现 |
| 称重记录管理 | 查询、筛选、编辑称重记录 | ⚠️ 数据层已支持，UI 未实现 |

### 1.3 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 7 / 10 / 11 |
| 运行时 | .NET Framework 4.7.2 |
| 数据库 | SQLite 3（嵌入式，无需安装） |
| 硬件 | RS-232/RS-485 串口 + 地磅仪表（可手动模式运行） |
| 打印机 | 可选（支持 Windows 系统打印机，热敏/A4/标准票据） |

### 1.4 设计原则

根据项目开发规范（`Claude开发规范.txt`），系统遵循以下设计原则：

1. **向后兼容**：不修改已有业务逻辑
2. **数据库稳定**：不修改已有字段名称
3. **协议不变**：不修改串口通信协议
4. **模块化**：新功能采用模块化设计
5. **单功能提交**：每次开发仅完成一个功能点
6. **硬件解耦**：不强制依赖硬件，支持手动模式运行
7. **接口优先**：通过接口实现模块解耦，避免直接依赖第三方 SDK

### 5.3 表结构详细设计

#### 5.3.1 WeighRecords（称重记录表）— 核心业务表

```sql
CREATE TABLE IF NOT EXISTS WeighRecords (
    Id              TEXT PRIMARY KEY,           -- GUID，32位N格式，主键
    PlateNumber     TEXT,                       -- 完整车牌号（如"沪A12345"）
    Province        TEXT,                       -- 省份简称（皖/京/沪...）
    PlateCode       TEXT,                       -- 车牌号码部分（如"A12345"）
    GrossWeight     REAL,                       -- 毛重（单位：吨）
    TareWeight      REAL,                       -- 皮重（单位：吨）
    NetWeight       REAL,                       -- 净重 = 毛重 - 皮重（单位：吨）
    CargoType       TEXT,                       -- 货物类型名称
    Sender          TEXT,                       -- 发货单位
    Receiver        TEXT,                       -- 收货单位
    DriverName      TEXT,                       -- 司机姓名
    DriverPhone     TEXT,                       -- 司机联系电话
    BusinessType    INTEGER,                    -- 0=采购入库 1=销售出库 2=内部调拨 3=其他
    Status          INTEGER,                    -- 0=第一次称重 1=第二次称重 2=已完成 3=已取消
    FirstWeighTime  DATETIME,                   -- 第一次称重（毛重）时间
    SecondWeighTime DATETIME,                   -- 第二次称重（皮重）时间
    CompleteTime    DATETIME,                   -- 完成时间
    OperatorId      TEXT,                       -- 操作员 ID
    OperatorName    TEXT,                       -- 操作员姓名
    Remark          TEXT,                       -- 备注
    PrintCount      INTEGER DEFAULT 0,          -- 打印次数
    IsUploaded      INTEGER DEFAULT 0,          -- 是否已上传 0=未上传 1=已上传
    CreateTime      DATETIME DEFAULT CURRENT_TIMESTAMP,  -- 记录创建时间
    UpdateTime      DATETIME DEFAULT CURRENT_TIMESTAMP,  -- 最后更新时间
    Category        INTEGER DEFAULT 0,          -- 0=有效 1=临时修改 2=废弃 3=待审核
    ModifyHistory   TEXT,                       -- 修改历史 JSON（[{ModifyTime,FieldName,OldValue,NewValue,...}]）
    ReviewerId      TEXT,                       -- 审核人 ID
    ReviewerName    TEXT,                       -- 审核人姓名
    ReviewTime      DATETIME                    -- 审核时间
);

-- 索引
CREATE INDEX IF NOT EXISTS IDX_PlateNumber ON WeighRecords(PlateNumber);
CREATE INDEX IF NOT EXISTS IDX_CreateTime   ON WeighRecords(CreateTime);
CREATE INDEX IF NOT EXISTS IDX_Status       ON WeighRecords(Status);
```

#### 5.3.2 Customers（客户表）

```sql

    Type          INTEGER,                      -- 0=供应商 1=客户 2=混合（既是供应商也是客户）
    ContactPerson TEXT,                         -- 联系人姓名
    Phone         TEXT,                         -- 联系电话
```

**停止位 "0" 选项**：comboBox5 代码中 Items 为 `{"1", "0"}`，当用户选择 "0" 时：
- 代码路径：`comboBox5.Text.Equals("1")` → false → `Equals("1.5")` → false → `Equals("2")` → false

### 8.4 数据接收与解析协议

#### 8.4.1 当前实际使用的协议（Form1 内置实现）

```
数据帧格式 (STX/ETX 包络):
┌──────┬──────────────────────────┬──────┐
│ 0x02 │    ASCII 数据载荷          │ 0x03 │
│ STX  │  例如: =0012345           │ ETX  │
└──────┴──────────────────────────┴──────┘
            │
            ▼
        剥离 STX/ETX → ASCII 解码 → "=0012345"
            │
            ▼
        提取等号后面部分 → "0012345"
            │
            ▼
        去前导零 → "12345"
            │
            ▼
        显示在 textBox6（重量显示区）
```

#### 8.4.2 处理流程（伪代码）

```
serialPort1_DataReceived(sender, e):
    num = serialPort1.ReadBufferSize
    received_buf = new byte[num]
    receive_count += num
    
    Invoke(UI线程):
        if HEX模式:
            foreach byte in received_buf:
                sb.Append(byte.ToString("X2") + " ")
        else:  // ASCII模式
            firstByte = serialPort1.ReadByte()
            if firstByte == 0x02:          // 检测到STX帧头
                for i in 0..(bytesRead-1):
                    byteData = ReadByte()
                    if byteData == 0x03:   // 检测到ETX帧尾
                        break
                    received_buf[i] = byteData
            
            Array.Reverse(received_buf)     // 字节反转
            asciiString = Encoding.ASCII.GetString(received_buf)
            textBox6.Text = asciiString.Substring(asciiString.IndexOf("=")+1).TrimStart('0')
        
        textBox_receive.AppendText(sb.ToString())
        label7.Text = "Rx:" + receive_count + "Bytes"
```

#### 8.4.3 ScaleService 支持的协议（扩展，尚未集成）

## 10、称重模块

### 10.1 称重业务模型

系统采用地磅行业标准的 **两次称重法**：

```
┌─────────────────────────────────────────────────────────────┐
│                      两次称重法流程                           │
│                                                             │
│  步骤 1: 第一次称重（重车/毛重 GrossWeight）                  │
│  ┌─────────────────────────────────────────────┐            │
│  │  车辆满载上磅 ─► 串口读取重量 ─► 点击"称取重车" │            │
│  │              textBox6 ───────► textBox1      │            │
│  └─────────────────────────────────────────────┘            │
│                         │                                   │
│                         ▼                                   │
│  步骤 2: 第二次称重（空车/皮重 TareWeight）                   │
│  ┌─────────────────────────────────────────────┐            │
│  │  车辆卸货后上磅 ─► 串口读取重量 ─► 点击"称取空车" │            │
│  │                textBox6 ───────► textBox2    │            │
│  └─────────────────────────────────────────────┘            │
│                         │                                   │
│                         ▼                                   │
│  步骤 3: 计算净重                                            │
│  ┌─────────────────────────────────────────────┐            │
│  │  点击"计算"按钮                                   │            │
│  │  NetWeight = GrossWeight - TareWeight        │            │
│  │  textBox3 = textBox1 - textBox2              │            │
│  └─────────────────────────────────────────────┘            │
└─────────────────────────────────────────────────────────────┘
```

### 10.2 UI 字段映射

#### 12.3.2 建议的统计 SQL 示例

```sql
-- 日报表：每日称重汇总
SELECT 
    DATE(CreateTime) AS 日期,
    COUNT(*) AS 称重次数,
    SUM(CASE WHEN BusinessType = 0 THEN 1 ELSE 0 END) AS 进厂次数,
    SUM(CASE WHEN BusinessType = 1 THEN 1 ELSE 0 END) AS 出厂次数,
    SUM(NetWeight) AS 总净重,
    AVG(NetWeight) AS 平均净重
FROM WeighRecords
WHERE Category = 0                     -- 仅有效记录
  AND CreateTime BETWEEN @start AND @end
GROUP BY DATE(CreateTime)
ORDER BY DATE(CreateTime) DESC;

-- 货物类型统计
SELECT 
    CargoType AS 货物类型,
    COUNT(*) AS 车次,
    SUM(NetWeight) AS 总净重,
    AVG(NetWeight) AS 平均单车净重
FROM WeighRecords
WHERE Category = 0
  AND CreateTime BETWEEN @start AND @end
GROUP BY CargoType
ORDER BY SUM(NetWeight) DESC;
```

## 13、异常处理

### 13.1 异常处理策略总览

系统采用**分散式 try-catch** 模式，没有全局异常处理器。

```
异常处理层级:
┌───────────────────────────────────────────────┐
│  UI 层 (Form1, UserLogin)                     │
│  · try-catch 包裹事件处理方法                  │
│  · catch 中: MessageBox + 蜂鸣               │
│  · 部分异常：重建对象/刷新状态                 │
├───────────────────────────────────────────────┤
│  服务层 (ScaleService)                         │
│  · 通过 ErrorOccurred 事件传播异常             │
│  · 方法返回 bool 表示成功/失败                 │
├───────────────────────────────────────────────┤
│  数据层 (DatabaseHelper)                      │
│  · catch 后返回 false / 空列表                │
│  · Initialize() 包装异常为业务异常抛出          │
├───────────────────────────────────────────────┤
│  基础设施层 (HTTPS)                            │
│  · 所有异常 catch 后返回 "" （静默吞掉）        │
│  · 不记录日志，不通知调用方失败原因              │
└───────────────────────────────────────────────┘
```

### 13.2 各模块异常处理详解

#### 13.2.1 串口操作异常

```csharp
// Form1.button1_Click — 打开/关闭串口
try {
    // 串口操作...
} catch (Exception ex) {
    serialPort1 = new SerialPort();           // 重建对象
    comboBox1.Items.Clear();                 // 刷新串口列表
    SystemSounds.Beep.Play();                 // 蜂鸣
    button1.Text = "打开串口";                // 恢复 UI
    MessageBox.Show(ex.Message);              // 弹窗显示
    // 恢复控件可用性
}
```

**特点**：
- ✅ 操作失败后尝试恢复可操作状态
- ✅ 物理信号（蜂鸣）提醒操作员
- ❌ 未记录日志
- ❌ 未区分异常类型（硬件断开 vs 参数错误）

#### 13.2.2 数据接收异常

```csharp
// Form1.serialPort1_DataReceived
try {
    // 解析数据...
} catch (Exception ex) {
    SystemSounds.Beep.Play();
    MessageBox.Show(ex.Message);
}
```

**⚠️ 风险**：DataReceived 在后台线程触发，异常时弹出 MessageBox 可能导致**大量连续弹窗**无法关闭（如串口持续收到损坏数据）。

#### 13.2.3 HTTP 通信异常

```csharp
// HTTPS.HttppPost — 所有 HTTP 方法统一模式
try {
    // HTTP 请求...
    return result;
} catch (Exception ex) {
    return "";  // 静默吞掉异常，返回空字符串
}
```

**⚠️ 风险**：
- 调用方无法区分"请求失败"和"返回空内容"
- 无重试机制
- 无超时配置（使用 .NET 默认超时）
- SSL 证书验证被全局跳过

#### 13.2.4 数据库操作异常

```csharp
// DatabaseHelper — 写操作
try {
    // SQL 执行...
    return true;
} catch (Exception) {
    return false;  // 吞掉异常，返回 false
}

// DatabaseHelper.Initialize — 初始化
try {
    // 建库建表...
} catch (Exception ex) {
    throw new Exception("数据库初始化失败：" + ex.Message);  // 包装后重新抛出
}
```

**特点**：
- 写操作返回 bool，不抛异常
- 初始化失败则直接 throw，应用无法启动
- ❌ 无数据完整性校验（如重量为负）

#### 13.2.5 ScaleService 异常处理

```csharp
// ScaleService — 事件驱动异常通知
catch (Exception ex) {
    ErrorOccurred?.Invoke("连接串口失败：" + ex.Message);
    _isConnected = false;
    return false;
}
```

**特点**：
- ✅ 通过事件传播错误，解耦 UI
- ✅ 内部状态同步更新
- ❌ 未区分可恢复异常与致命异常

### 13.3 异常处理缺陷汇总

| 问题 | 严重程度 | 位置 |
|------|----------|------|
| HTTP 异常静默吞掉 | 🔴 高 | HTTPS.cs 全部方法 |
| DataReceived 中 MessageBox 可能死循环弹窗 | 🔴 高 | Form1.serialPort1_DataReceived |
| 计算净重时空 if 块不处理异常 | 🟡 中 | Form1.button5_Click |
| 全局跳过 SSL 证书验证 | 🟡 中 | HTTPS.cs |
| 无日志记录任何异常 | 🟡 中 | 全局 |
| 未使用 using 确保 SerialPort 释放 | 🟡 中 | Form1（异常时 new SerialPort 丢弃旧对象） |
| 异常后无自动恢复机制 | 🟢 低 | 全局 |

### 13.4 设计建议

```
建议的异常处理架构:

┌─────────────────────────────────────────┐
│         GlobalExceptionHandler           │
│  Application.ThreadException 处理        │
│  AppDomain.UnhandledException 处理       │
├─────────────────────────────────────────┤
│  · 记录完整堆栈到日志文件                 │
│  · 显示用户友好错误对话框                 │
│  · 对于可恢复异常：恢复默认状态            │
│  · 对于致命异常：优雅关闭应用              │
└─────────────────────────────────────────┘

建议的异常分类处理:
┌──────────────┬──────────────────────────┐
│ 可恢复异常    │ 串口断开、网络超时          │
│              │ → 自动重试 + 状态提示       │
├──────────────┼──────────────────────────┤
│ 业务异常      │ 车牌为空、重量异常          │
│              │ → 校验提示 + 阻止操作       │
├──────────────┼──────────────────────────┤
│ 系统异常      │ 数据库损坏、内存不足        │
│              │ → 日志记录 + 安全退出       │
└──────────────┴──────────────────────────┘
```
